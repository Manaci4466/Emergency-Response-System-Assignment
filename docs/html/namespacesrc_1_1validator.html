Detailed Description

Phase 7: independent plan validator.

INDEPENDENT of the planner: it reads plan.json and the raw scenario files and uses only data_loader and cost_model (the model's DEFINITION of travel time and P(Blocked)). It never imports search, allocation or simulator; a test checks that. Travel times are recomputed by summing the edge costs along the path given in the plan, so a wrong route or a wrong cost in the planner shows up here.

Errors (the plan breaks a hard constraint):

  • schema: entry is not {responder_id: str, incident_id: str, path: non-empty list, time: number ≥ 0}
  • unknown_id: responder or incident id not in the scenario
  • duplicate: incident assigned more than once (the extra entry is not checked further)
  • capability: responder lacks the required capability
  • path_start: first node is not where the responder is at that moment (start_location for its first job, the previous incident's location afterwards)
  • path_end: last node is not the incident location
  • no_road: consecutive nodes without a DIRECTED road between them
  • blocked_road: road with P(Blocked) ≥ tau
  • repeated_node: the path visits a node twice
  • before_timestamp: job starts before the incident is known (clairvoyance)
  • before_available: job starts before the responder's time_until_available
  • overlap: per responder (sorted by time) a job starts before the previous arrival + time_required (recomputed, tolerance 1e-6)

Warnings: late (recomputed arrival > deadline) and unhandled (incident missing from the plan).

Note
LIMITATION: validity is relative to the BELIEVED road states (P(Blocked) < tau) and to EXPECTED travel times under the model. A valid plan can still use a road that is in reality blocked; the validator shares the cost model, so a wrong model is not detected here (the unit tests do that).
